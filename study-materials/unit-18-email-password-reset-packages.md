## 18.1 The Email System — MailKit + Gmail SMTP

Sha8alny sends emails for one main purpose: password reset codes. The email system is built on two NuGet packages:

- **MailKit 4.9.0** — the SMTP client that connects to Gmail and sends the email
- **MimeKit 4.9.0** — the library that constructs the email message itself (headers, HTML body, attachments)

Think of it this way: **MimeKit builds the letter, MailKit puts it in the envelope and mails it.**

**Configuration in `appsettings.json`:**
```json
{
  "MailSettings": {
    "EmailFrom": "noreply@sha8alny.com",
    "DisplayName": "Sha8alny Support",
    "SmtpHost": "smtp.gmail.com",
    "SmtpPort": 587,
    "SmtpUser": "sha8alny2026@gmail.com",
    "SmtpPass": "samp pjnc tqpm vehe"
  }
}
```

Port 587 is the standard SMTP port for **STARTTLS** — the connection starts unencrypted and then upgrades to TLS encryption. This is different from port 465, which uses implicit TLS from the start. Gmail requires STARTTLS on port 587 for app-to-app sending.

The `SmtpPass` is a **Gmail App Password** — a 16-character code generated by Google specifically for apps that cannot use OAuth2. It is not the account's real password. Google requires this when "2-Step Verification" is enabled on the account.

**`MailService.SendEmailAsync` — what happens step by step:**

```csharp
public async Task SendEmailAsync(string toEmail, string subject, string htmlBody)
{
    // 1. Build the message with MimeKit
    var email = new MimeMessage();
    email.From.Add(new MailboxAddress("Sha8alny Support", "noreply@sha8alny.com"));
    email.To.Add(MailboxAddress.Parse(toEmail));
    email.Subject = subject;
    email.Body = new BodyBuilder { HtmlBody = htmlBody }.ToMessageBody();

    // 2. Connect to Gmail SMTP with MailKit
    using var smtp = new SmtpClient();
    await smtp.ConnectAsync("smtp.gmail.com", 587, SecureSocketOptions.StartTls);
    await smtp.AuthenticateAsync("sha8alny2026@gmail.com", "samp pjnc tqpm vehe");

    // 3. Send, then disconnect
    await smtp.SendAsync(email);
    await smtp.DisconnectAsync(true);
}
```

If the send fails (Gmail is down, wrong credentials, etc.), the exception is **not swallowed** — it is logged and rethrown. The caller (AuthService) decides what to do. This is the opposite of the SignalR notifier's silent-failure pattern, because email is part of the critical password reset flow.

## 18.2 Why MailKit Instead of the Built-in `System.Net.Mail`?

`System.Net.Mail.SmtpClient` is the built-in .NET email client. It works but has problems:

1. **Marked as deprecated for new development** — Microsoft's own documentation suggests using MailKit instead
2. **No async support** — `SmtpClient.SendAsync` is fake-async; it runs synchronously and wraps in Task, blocking a thread
3. **No OAUTH2 support** — MailKit supports modern authentication methods
4. **Less reliable TLS handling** — MailKit has better negotiation for StartTLS vs SSL

MailKit is the industry standard for .NET email. It is actively maintained and used by major .NET projects.

## 18.3 The Password Reset Flow — End-to-End

This is the complete flow when a user clicks "Forgot my password":

**Step 1 — User calls `POST /api/Auth/forgot-password`:**
```json
{ "email": "ahmad@example.com" }
```

**Step 2 — `AuthService.ForgotPasswordAsync` runs:**
```csharp
var user = await _unitOfWork.Users.FindSingleAsync(u => u.Email == email);

// IMPORTANT: Always return the same message whether user exists or not.
// This prevents email enumeration: an attacker cannot tell if an email
// is registered by checking whether the response differs.
if (user is null)
    return ServiceResponse<string>.Success("If an account with that email exists, a reset code has been sent.");

// Generate a 6-digit numeric code
var code = new Random().Next(100000, 999999).ToString();

// Store the code and its expiry on the User record
user.PasswordResetToken = code;           // e.g., "482916"
user.ResetTokenExpires = DateTime.UtcNow.AddMinutes(15);  // expires in 15 minutes

_unitOfWork.Users.Update(user);
await _unitOfWork.SaveAsync();

// Send the email with the code
await _mailService.SendEmailAsync(user.Email, "Sha8alny - Password Reset Code", htmlBody);
```

The **email enumeration protection** is a security best practice: if the server returned "user not found" for unknown emails, an attacker could probe which email addresses are registered. By always returning the same success message, the server reveals nothing.

**Step 3 — User receives email with the 6-digit code (expires in 15 minutes)**

**Step 4 — User calls `POST /api/Auth/reset-password`:**
```json
{
  "email": "ahmad@example.com",
  "token": "482916",
  "newPassword": "NewStrongPassword123!"
}
```

**Step 5 — `AuthService.ResetPasswordAsync` runs:**
```csharp
var user = await _unitOfWork.Users.FindSingleAsync(u => u.Email == dto.Email);
if (user is null)
    return ServiceResponse<string>.Failure("Invalid request.");

// Validate: code must match AND must not be expired
if (user.PasswordResetToken != dto.Token ||
    user.ResetTokenExpires == null ||
    user.ResetTokenExpires <= DateTime.UtcNow)
    return ServiceResponse<string>.Failure("Invalid or expired reset code.");

// Hash the new password
user.PasswordHash = BC.HashPassword(dto.NewPassword);

// Clear the token so it cannot be reused
user.PasswordResetToken = null;
user.ResetTokenExpires = null;
user.UpdatedAt = DateTime.UtcNow;

_unitOfWork.Users.Update(user);
await _unitOfWork.SaveAsync();
```

Three security checks happen together:
1. **Code matches** — string equality check
2. **Token not null** — a user who never requested a reset has no token
3. **Not expired** — `ResetTokenExpires <= DateTime.UtcNow` catches codes older than 15 minutes

After reset, the token fields are set to `null` — **the code can only be used once**.

**The full flow as a diagram:**
```
User              Flutter App          AuthController       AuthService          MailService/Gmail
  |                    |                     |                    |                     |
  |-- "Forgot pwd" --> |                     |                    |                     |
  |                    |-- POST /forgot-pwd->|                    |                     |
  |                    |                     |-- ForgotPwdAsync ->|                     |
  |                    |                     |                    |-- Generate code ---> |
  |                    |                     |                    |   Store in DB        |
  |                    |                     |                    |-- SendEmailAsync --> |
  |                    |                     |                    |                     |-- SMTP to Gmail ->
  |<--- Email arrives -+---------------------+--------------------+---------------------|
  |-- Types code ----> |                     |                    |                     |
  |                    |-- POST /reset-pwd ->|                    |                     |
  |                    |                     |-- ResetPwdAsync -->|                     |
  |                    |                     |                    |-- Validate code      |
  |                    |                     |                    |-- Hash new password  |
  |                    |                     |                    |-- Clear token        |
  |<-- "Success" ------+---------------------+--------------------+                     |
```

## 18.4 The `AuthController` Endpoints — Full Map

| Endpoint | Auth | What it does |
|---|---|---|
| `POST /api/Auth/register` | None | Creates user, returns JWT |
| `POST /api/Auth/login` | None | Validates password, returns JWT |
| `GET /api/Auth/me` | Required | Returns current user's display info |
| `POST /api/Auth/forgot-password` | None | Sends 6-digit code to email |
| `POST /api/Auth/reset-password` | None | Validates code, sets new password |

The `GET /me` endpoint shows how `GetCurrentUserAsync` resolves display names differently per role:
- **Student** → reads `Student.FirstName + LastName`
- **Company** → reads `Company.CompanyName`
- **Admin/University** → reads `User.FirstName + LastName` or falls back to email

This is because the `User` table stores the account credentials only. The actual profile (name, logo, etc.) lives in `Student` or `Company`. `GetCurrentUserAsync` bridges that gap.

## 18.5 NuGet Package Justifications — "Why Did You Use X?"

This is the most common type of question in a defense about a framework/technology choice. Here is the full list with justifications.

---

### BCrypt.Net-Next 4.0.3
**What it does:** Hashes passwords before storing them.

**Why BCrypt instead of SHA-256 or MD5?**
MD5 and SHA-256 are fast hashing algorithms — designed to process data quickly. Fast is bad for passwords: an attacker with a leaked database can try billions of guesses per second using GPUs.

BCrypt is **intentionally slow** — it has a "work factor" (also called cost) that makes each hash computation take ~100ms. An attacker hashing 1 billion guesses would take decades instead of minutes. BCrypt also automatically generates a **salt** (random data mixed into each hash), so two users with the same password get different hashes — rainbow table attacks are useless.

Usage in the codebase:
```csharp
// Registration: hash the password
var passwordHash = BC.HashPassword(dto.Password);

// Login: verify the entered password against the stored hash
if (!BC.Verify(dto.Password, user.PasswordHash))
    return failure;
```

---

### Microsoft.AspNetCore.Authentication.JwtBearer 9.0.0
**What it does:** Validates JWT tokens on every request.

**Why JWT instead of sessions?**
Sessions require the server to store session state — a database table or in-memory store of "who is logged in." On Google Cloud Run, each request may hit a different container instance. Sessions break unless you share state across instances.

JWT is **stateless**: the token itself contains the user's identity and role, signed with a secret key. Any server instance can validate it without a central state store. The trade-off is that tokens cannot be invalidated before they expire (see Unit 6 §6.7 for the ban limitation).

---

### Entity Framework Core 9.0.10 + Microsoft.EntityFrameworkCore.SqlServer 9.0.10
**What it does:** Object-Relational Mapper — writes SQL for you based on C# objects.

**Why EF Core instead of raw ADO.NET or Dapper?**

| Feature | EF Core | Dapper | ADO.NET |
|---|---|---|---|
| Write SQL manually? | No — EF generates it | Yes | Yes |
| Change tracking | Built-in | None | None |
| Migrations | Built-in | Manual | Manual |
| LINQ queries | Full LINQ | No | No |
| Learning curve | Medium | Low | High |

For a graduation project with 30 entities and 9 migrations, EF Core's change tracking and migration system saves thousands of lines of handwritten SQL. Dapper is faster for read-heavy workloads with complex queries; EF Core is better when you also need write operations and schema management.

---

### SixLabors.ImageSharp 3.1.6
**What it does:** Resizes images and converts them to WebP format.

**Why ImageSharp instead of `System.Drawing`?**
`System.Drawing` (the built-in .NET image library) depends on `GDI+` — a Windows-only graphics library. On Linux containers (Google Cloud Run runs Linux), `System.Drawing` either crashes or requires extra native libraries. ImageSharp is **pure C#**, works on all platforms including Linux containers, and is actively maintained.

Usage (from Unit 7):
```
Upload: resize to max 1920px, convert to WebP at 80% quality
Thumbnail: resize to 300×300 for profile pictures
```

WebP produces ~30% smaller files than JPEG at equivalent visual quality, which reduces storage costs and speeds up page loads.

---

### SignalR (Microsoft.AspNetCore.SignalR — built into ASP.NET Core)
**What it does:** Manages persistent WebSocket connections for real-time messaging.

**Why SignalR instead of raw WebSockets?**
Raw WebSockets require you to manage: connection tracking (which socket belongs to which user), reconnection on network drops, fallback for environments that block WebSockets (proxies, older browsers), and message serialization.

SignalR handles all of this. It maps connections to users via JWT claims automatically, falls back to Server-Sent Events or Long Polling when WebSockets are unavailable, and serializes/deserializes messages to JSON automatically. The `IHubContext<T>` allows server-side code to push to any user without that user having sent a request.

---

### MailKit 4.9.0 + MimeKit 4.9.0
**Already covered in §18.1 and §18.2 above.**
Short version: MailKit is the .NET-recommended replacement for `System.Net.Mail.SmtpClient`, which is deprecated for new development and has no true async support.

---

### nClam 6.0.1
**What it does:** Connects to a ClamAV virus scanner to check uploaded files.

**Why is it installed but disabled?**
ClamAV runs as a separate process (a daemon). On a local machine, it works perfectly. On Google Cloud Run, the ClamAV daemon would need to run as a **sidecar container** — a separate container that runs alongside the API container on the same instance. Cloud Run's sidecar support is available but adds significant deployment complexity for a graduation project.

The interface is preserved (`IVirusScanService`) and the implementation (`ClamAvService`) always returns `true` (file is clean) as a stub. If the project moves to a more controlled infrastructure, swapping in the real implementation requires only one line change in `Program.cs` — the architecture already supports it.

---

### AutoMapper 13.0.1
**What it does:** Copies data from domain entities to DTOs without manual property assignment.

**Why AutoMapper instead of writing it manually?**
Without AutoMapper:
```csharp
var dto = new StudentResponseDto
{
    StudentID = student.StudentID,
    FirstName = student.FirstName,
    LastName = student.LastName,
    Email = student.User.Email,
    // ... 20 more properties
};
```

With AutoMapper:
```csharp
var dto = _mapper.Map<StudentResponseDto>(student);
```

For 30 entities and 60+ DTOs, mapping manually would be hundreds of repetitive lines that must be updated every time a property is added. AutoMapper handles standard cases (same property name = copy), and custom mappings are declared in `MappingProfile.cs` (e.g., concatenating `FirstName + LastName` into `FullName`).

---

### Swashbuckle.AspNetCore 7.3.1
**What it does:** Generates the Swagger/OpenAPI documentation UI.

**Why Swagger?**
Swagger generates interactive API documentation from the controller code. Every endpoint, its parameters, its request body shape, and its response shape are automatically documented. The Flutter frontend team used the Swagger UI at `http://localhost:5000` (configured at the root URL — `RoutePrefix = ""`) to see exactly what the API expects without reading the C# code.

The `[ApiController]` attribute combined with XML doc comments (`/// <summary>`) generates rich documentation with descriptions for each endpoint.

---

### Microsoft.Extensions.Options 9.0.0
**What it does:** Provides the `IOptions<T>` pattern for binding `appsettings.json` sections to typed C# classes.

Instead of:
```csharp
var key = Configuration["JwtSettings:Key"];  // string, no type safety
```

With Options:
```csharp
var key = _jwtOptions.Key;  // strongly typed JwtOptions class
```

`JwtOptions` and `MailSettings` are both registered with `builder.Services.Configure<T>()` in `Program.cs` and injected as `IOptions<T>` wherever needed.

## 18.6 CORS — The AllowAll Policy

CORS (Cross-Origin Resource Sharing) is a browser security mechanism that blocks web pages from calling APIs on a different domain. Without CORS headers, the Flutter Web version and any browser-based frontend cannot call the API.

The current configuration in `Program.cs`:
```csharp
builder.Services.AddCors(options =>
{
    options.AddPolicy("AllowAll", policy =>
    {
        policy.AllowAnyOrigin()
              .AllowAnyMethod()
              .AllowAnyHeader();
    });
});
```

**"AllowAll" means:** any domain, any HTTP method, any header — no restrictions.

**Is this safe for production?**
No — in production, you would restrict `AllowAnyOrigin()` to specific trusted domains (e.g., `WithOrigins("https://sha8alny.com")`). Allowing all origins means any website in the world could make API calls on behalf of a logged-in user.

**Why AllowAll for this project?**
For a graduation project with a Flutter mobile app (which is not a browser and does not have CORS restrictions), the CORS policy primarily matters for browser testing via Swagger and any web prototype. Using AllowAll simplifies development — no time spent debugging CORS errors. In a production deployment, this would be the first security setting to tighten.

## 18.7 Unexplained Domain Entities — ProjectGroup, ActivityLog, CompletedOpportunity

Three entities exist in `Sh8lny.Domain.Models` but are not wired into any service endpoints. They are **scaffolded for future features** that were designed but not implemented before the graduation deadline.

### `ProjectGroup` / `GroupMember`
```
ProjectGroup: GroupID | ProjectID | GroupName | Description | MaxMembers | CreatedAt
GroupMember: [GroupID, UserID junction table]
```
**Purpose:** Allows a project to be divided into teams. Multiple students can join the same project but work in different groups. A `GroupID` can also be linked to a `Conversation`, enabling group chat per team. Not implemented in any service because single-student applications cover all current use cases.

### `ActivityLog`
```
ActivityLog: LogID | UserID | ActivityType | Description | RelatedEntityType | RelatedEntityID | IPAddress | UserAgent | CreatedAt
```
**Purpose:** Audit trail — records who did what and when, with the IP address and browser/device identifier. Useful for security reviews ("who deleted this project?") and admin investigations. The entity is defined but no service currently writes to the `ActivityLog` table.

### `CompletedOpportunity`
```
CompletedOpportunity: CompletedOpportunityID | StudentID | ProjectID | ApplicationID | CertificateID
  | OpportunityTitle | StartDate | EndDate | DurationInDays
  | Rating | StudentFeedback | CompanyFeedback | Achievements | SkillsGained
  | IsVerified | VerifiedBy | IsVisibleOnProfile | ...
```
**Purpose:** A rich summary record of a completed engagement — like a LinkedIn entry, but auto-populated from the platform data. It consolidates the certificate, reviews, duration, and skills gained into one queryable record. `CompleteJobAsync` (Unit 10) does not yet write a `CompletedOpportunity` row, but the entity is ready for when that step is implemented.

**In your defense:** "These three entities are in the domain model as part of the planned feature roadmap. The schema is designed, the relationships are configured in FluentAPI, and the tables exist via migrations. The service layer implementation is deferred because the graduation deadline required prioritizing the core marketplace flow — apply, accept, execute, pay, review — which is complete."

## 18.9 Self-Check Questions

**Q1: What is a Gmail App Password and why is it used instead of the real account password?**
A Gmail App Password is a 16-character code generated by Google for apps that cannot use OAuth2 (like a server-side SMTP client). When "2-Step Verification" is enabled on a Google account, the regular password cannot be used by apps — Google requires an App Password instead. It grants SMTP access without exposing the full account credentials.

**Q2: Why does `ForgotPasswordAsync` always return success even if the email doesn't exist?**
To prevent **email enumeration**. If the server returned "email not found," an attacker could use the endpoint to discover which email addresses are registered on the platform by sending thousands of requests. Returning the same message regardless of whether the user exists prevents this information leak.

**Q3: What happens if the user calls `reset-password` with a valid code but it's 20 minutes old?**
`ResetPasswordAsync` checks `user.ResetTokenExpires <= DateTime.UtcNow`. Since the token expires 15 minutes after generation, a 20-minute-old code has already passed its expiry. The method returns `ServiceResponse<string>.Failure("Invalid or expired reset code.")` and the password is not changed.

**Q4: Why is BCrypt preferred over SHA-256 for password storage?**
SHA-256 is fast — designed for checksums and data integrity. Fast is dangerous for passwords: GPUs can compute billions of SHA-256 hashes per second, making brute-force feasible. BCrypt is intentionally slow (~100ms per hash by design), uses a work factor that can be increased as hardware gets faster, and automatically generates a unique salt per hash — defeating rainbow table attacks.

**Q5: What does MailKit's `SecureSocketOptions.StartTls` mean?**
It means the initial TCP connection starts on port 587 without encryption, then the client sends the `STARTTLS` command to upgrade the connection to TLS encryption before sending credentials or email content. This is different from `SslOnConnect` (port 465), which uses TLS from the very first byte.

**Q6: Why use AutoMapper at all — isn't it just magic that hides what's happening?**
AutoMapper is configuration over code. The mappings are declared explicitly in `MappingProfile.cs` — there is nothing hidden. The alternative is writing 300+ lines of property-copy code that must be updated every time a property is added or renamed. For 30 entities and 60+ DTOs, AutoMapper eliminates a major maintenance burden while keeping all mapping logic in one place.

**Q7: What is `IOptions<T>` and why is it used for `JwtOptions` and `MailSettings`?**
`IOptions<T>` is ASP.NET Core's typed configuration system. Instead of reading raw strings from `Configuration["Section:Key"]` (no type safety, easy to misspell), you define a class like `JwtOptions { string Key; string Issuer; ... }` and bind the appsettings section to it. The bound object is injected wherever needed. If the config key is wrong, the app fails at startup with a clear error rather than failing silently at runtime.

**Q8: What is the purpose of `ProjectGroup` and why isn't it implemented?**
`ProjectGroup` allows a project to be split into student teams, each with a group name, member limit, and associated group chat. The entity, database table, and FluentAPI configuration all exist. The service-layer implementation was not prioritized because all current use cases involve individual student applications. The schema is ready for the feature when needed.
